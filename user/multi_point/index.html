    Multi-point Optimisation¶

    When one function evaluation takes long, evaluating several points at the same time shortens the wall-clock time. The multi-point optimisers use MPI: every MPI rank is a process that can evaluate the objective function.

    MPI required

    EgoMPI and EgoAsync need an MPI implementation (OpenMPI, MPICH or MS-MPI), mpi4py, and at least two ranks. Otherwise they fall back to EgoSequential with a warning in the log.

    Synchronous or Asynchronous¶

    EgoMPI (synchronous) EgoAsync (asynchronous)
    Points per round number_new_points per iteration, at most one per rank One new point for every rank that becomes free
    Who evaluates All ranks, including rank 0 Ranks 1 to N-1; rank 0 only runs the optimiser
    Waits for All points of the iteration Nothing: a free rank gets a new point immediately
    Iterations Yes (max_iterations applies) No (results are numbered in arrival order; max_iterations is not used)
    Best when Evaluation times are similar Evaluation times differ (e.g. multi-fidelity)

    How Several Points Are Chosen¶

    An infill strategy proposes one point from the current surrogate. To propose more points before the results are known, the optimiser temporarily adds the pending points to the surrogate with an assumed value, and asks the infill strategy again. The assumed value is set by multipoint_algorithm (under "optimisation"):

    • "KB" (Kriging Believer, default): the surrogate's own prediction at the pending point, at the point's fidelity when the surrogate supports that (HK, MFK), and the HF prediction otherwise.
    • "CL" (Constant Liar): one constant value for all pending points, the minimum, mean or maximum (constant_liar_lie) of the sample values of the highest fidelity that has samples.

    Proposed points that duplicate a sample, a pending point, or another point of the same batch are replaced by the same location at a higher fidelity, or by a random point if no higher fidelity is available.

    Running¶

    Start the script with the MPI launcher, with one process per rank. Every rank runs the same script:

    mpiexec -n 4 python examples/04_multi_point_optimisation.py

    sbo.run() must be called on every rank. Only rank 0 returns the optimum; the other ranks return an empty dict, so save or print the results on rank 0 only:

    from mpi4py import MPI

optimum = sbo.run()
if MPI.COMM_WORLD.Get_rank() == 0:
    print(optimum)

    On a cluster, see Running on HPC.

    Example¶

    examples/04_multi_point_optimisation.py minimises x² with EgoAsync:

    """
Basic multi-point optimisation.

The minimal setup to perform a multi-point optimisation.
Note that for running multi-point optimisations MPI should be installed. And at least
two ranks should be available. Otherwise the optimisation will be run using a
single-point optimisation (EgoSequential)

Expected output:
    Optimum at x = [0], f = 0.

Run with:
    mpiexec -n <N_CORES> python examples/04_multi_point_optimisation.py
With:
    - The mpiexec call can depend per used MPI.
    - <N_CORES> should be replaced with the number of cores to be used.
"""

import numpy as np

from sbo import SBO, Config


# Define the objective function
def optimisation_function(x: np.ndarray) -> np.ndarray:
    """The optimisation function."""
    return x**2


# Generate the config file to define the optimisation problem
config = Config(
    used_algorithms={
        "optimisation": "EgoAsync",
        "infill": "EI",
        "surrogate": "KRG",
    },
    lb=[-5],
    ub=[5],
    functions=[optimisation_function],
)

# Instantiate the sbo
sbo = SBO(config)

# Run the optimisation
# The optimum has the type dict: {'coord': np.ndarray, 'value': float, 'fid': int}
# Note: only rank 0 returns the optimum, all other ranks return an empty dict.
# The sbo.run() should be called on every rank.
optimum = sbo.run()
